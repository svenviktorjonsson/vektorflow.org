0.4.7 structural-suffix compiler baseline

Read the 0.4.7 draft release notes. This benchmark preview is public, but compiler downloads and the browser runtime are not published yet.

Four compiler targets passed the same four suffix workloads with ten runs per workload, from one verified Actions run using source commit 03560e3209622d860689b11bfdd8e4d0b9a78a65. The canonical source hashes agree across all targets. These are compilation baselines for the next optimization round, not evidence of a runtime speedup. Native lanes first ran semantic tests and then compiled ten independent native artifacts. Values below are mean ± sample SD of compiler diagnostic total milliseconds on each runner.

The WebAssembly compiler preserved suffix metadata in typed IR, emitted a deterministic, valid, import-free artifact, and executed its bit tests on every sample. Its in-process compile-and-emit means were 2474.429 ± 954.974, 53.439 ± 9.885, 1854.346 ± 49.324, and 1926.028 ± 22.727 ms in the same corpus order. WASM report. Different hosts and measurement paths make these rows unsuitable for cross-platform speed rankings.

The JSON receipts include all raw samples, source and compiler hashes, and host details; matching JSON files accompany the Linux, macOS, and WASM reports. The source corpus covers index/coordinate sum steps, arbitrary suffix labels, numerical interpolation and integration, and symbolic integration. It does not prove every 0.4.7 language feature or a full release package.
