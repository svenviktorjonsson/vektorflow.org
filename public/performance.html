The cost of searching

The native compiler considers alternative execution policies and checks their results. Its published compile times include a fresh policy search: roughly 300 ms for spectral norm, 110 ms for Fannkuch and 122 ms for N-body on this runner. Faster execution can cost more compilation time.

0.4.7 structural-suffix compiler baseline

Read the 0.4.7 release notes. This limited-target 0.4.7 baseline covers Windows x64, Linux x64, and browser WebAssembly. The macOS ARM64 runner was unavailable for this compiler revision; older macOS measurements are not presented as evidence for it.

All three available compiler targets passed the same four suffix workloads with ten runs per workload. Their canonical workload source hashes match. The compiler source is based on e404879d; each JSON receipt records the exact compiler SHA-256, source hashes, host, and raw samples. These are compilation baselines for a later optimization round, not evidence of a runtime speedup. Native lanes first ran semantic tests and then compiled ten independent native artifacts. Values below are mean ± sample SD of compiler diagnostic total milliseconds on each host.

Windows report · Linux report

The WebAssembly compiler preserved suffix metadata in typed IR, emitted a deterministic, valid, import-free artifact, and executed its bit tests on every sample. Its in-process compile-and-emit means were 2007.654 ± 262.131, 52.651 ± 13.782, 3156.231 ± 1276.178, and 1931.962 ± 95.378 ms in the same corpus order. WASM report. Different hosts and measurement paths make these rows unsuitable for cross-platform speed rankings.

Matching JSON files accompany the Linux and WASM reports. The source corpus covers index/coordinate sum steps, arbitrary suffix labels, numerical interpolation and integration, and symbolic integration. It does not prove every 0.4.7 language feature, package closure, or macOS ARM64 behavior.
