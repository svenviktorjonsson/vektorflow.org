VKF 0.2.0 — Explicit Structures And Faster Native Kernels

VKF 0.2.0 tightens the language model and improves direct x64 code generation without adding a runtime dependency.

Language

  • Automatic typed-function application descends recursively through vectors only. Tuples and records remain whole values and require an exact function parameter or an explicit operator overload.
  • Fixed nested vectors reduce recursively, and stat.sum(axis:) supports an integer or tuple of axes, including negative axes.
  • Simple bound indices use value.index; computed indices use value.(expression). The compiler rejects an unparenthesized computed name where evaluation would otherwise be ambiguous.
  • Indented pipes are value-producing scopes. A following pipe stage receives the preceding stage's final value through $; an unparenthesized pipe inside [] or {} generates that container.
  • Public examples use compact range pipes, explicit dotted updates, evaluated computed indices, vector arithmetic, and grouped records instead of manual counter loops and flat component variables.

Native Compiler

  • Aggregate helper calls can inline without copying an unchanged structured result back onto itself.
  • Integral index origins survive scalar coalescing, enabling guarded fixed-loop bounds proofs while preserving runtime errors for unproven and fractional indices.
  • Integer comparisons branch directly, power-of-two remainder checks use low bits, and recognized fixed shifts and copies use dedicated integer lowering.
  • Backward-branch loop headers are aligned, and proven two-pointer prefix reversals lower as one tight fixed-vector loop with a single base address.
  • Spectral-norm matrix reductions recover their packed AVX2/FMA path across an empty range-pipe continuation label.
  • Constant fixed-vector frame indices lower as direct addresses instead of rebuilding a base pointer for each access.
  • Three-component affine and scaled updates fuse into compact vector kernels. N-body pair interactions keep displacement, magnitude, and masses in registers and use packed FMA for the x/y velocity lanes while preserving the scalar evaluation order.
  • The tuner always measures the fully enabled primary policy, caches the exact policy whose code was executed and validated, and exposes its canonical mask, code fingerprint, search time, and cache state in compiler diagnostics.
  • Runtime evidence reuses one exact selected policy for both the executable and raw machine entry, preventing two independent empirical searches from being compared as if they were one artifact.
  • Native string-multiset transfers preserve owned operands across calls.
  • Lexically resolved typed loads take precedence over same-named module bindings during machine-layout selection.
  • Scalar power shortcuts reject complex layouts, and component lowering now supports fixed collection literals used in nested-vector updates.

Documentation And Verification

  • The landing README contains installation, status, core examples, output, and one controlled timing table. The numbered language reference now lives only in docs/language-guide.md; duplicated landing and release material was removed from it.
  • The native VKF suite contains 332 passing tests and includes success and expected-compile-error cases.
  • Every documented program is compiled and executed 10 times on Windows x64, Linux x64, and macOS ARM64; each platform requires byte-identical output.
  • The release comparison uses the large spectral-norm, Fannkuch-redux, and N-body kernels. VKF, C, Rust, and Zig run interleaved on one Linux x64 host; the release gate requires every same-host raw-kernel ratio to remain below 2×.
  • Raw timing rotates languages in five-call steady-state batches; fresh-process output verification uses a separate 10-run count and is not mixed into the raw-kernel table.
  • Each of the 100 measured VKF compilations uses a fresh path and forces an uncached empirical policy search. Search time is included in end-to-end and compiler-core time and is also recorded separately.
  • On the controlled Ubuntu 24.04 x64 runner, the final 1,000-run raw means are spectral norm 6.460 ± 0.134 ms, Fannkuch 31.508 ± 0.396 ms, and N-body 4.247 ± 0.052 ms. Every VKF/C, VKF/Rust, and VKF/Zig ratio is below 2×; the largest is N-body versus Rust at 1.935×.
  • Corresponding end-to-end VKF compile means are 247.419 ms, 81.572 ms, and 47.083 ms. Those totals include fresh policy searches averaging 80.785 ms, 71.822 ms, and 22.298 ms, respectively.
  • Automatic GitHub Pages deployment was removed. GitHub's README remains the project landing page.

The installed compiler still directly emits PE, ELF, or Mach-O executables and does not require Python, a C++ compiler, an assembler, or a separate linker. physics, ui, and symbolic remain excluded rather than shipping partial or legacy fallbacks.
