VKF Standard Library

The standard library is separate from VKF syntax. This page describes each published library, how to bring it into scope, what it is useful for, and a runnable example. The syntax reference explains the language constructs used by those examples.

Importing and using a library

A dotted name on the right of a declaration creates a module handle, as in math: .math; calls then remain qualified as math.sqrt(...). A leading colon spills public names into the current scope, as in :.linalg; functions such as dot(...) can then be called directly. Nested modules use the same forms, including :.physics.units.

Qualified imports make dependencies obvious and are the default in the examples below. Spilling is useful for mathematical libraries where repeated qualification would obscure a formula. Each editor starts with the relevant import and can be compiled in the browser when that library has a browser-safe implementation. Native-only capabilities are labelled explicitly.

2. stat

Functions include sum, mean, count, min, max, range, variance, std, percentile, median, iqr, mode, zscore, normalize, covariance, correlation, clamp, and sign. sum reduces every nested vector dimension by default. The preferred compile-time form names the structural dimension directly: stat.sum_j(values_ij). The explicit axis: argument remains available for compatibility.

For a matrix, axis:0 reduces rows and returns column sums; axis:1 reduces columns and returns row sums. A tuple such as axis:(0, 2) reduces both named dimensions. Axis reduction currently requires a fixed rectangular numeric vector. Duplicate and out-of-range axes are compile errors. variance and std accept ddof; zero is the population form and one is the sample form.

For compile-time dimensions, the result keeps every non-reduced dimension:

For example, stat.sum_i(matrix_ij) produces the remaining j values, while stat.sum_j(matrix_ij) produces the remaining i values. An index-space stride is written stat.sum_i(values_i, i_step:2). With sampled values and a coordinate vector, stat.sum_x(samples_x, x:x, x_from:0, x_to:2, x_step:0.5) interpolates at the coordinate lattice 0, .5, 1, ... before reducing.

All bound controls are axis-qualified (x_from, x_to, x_step). Without a coordinate vector, a step is a non-zero integer index stride. With x: it is a coordinate-space step and the sampled values are linearly interpolated at the resulting lattice. A reversed sum whose step has the wrong direction is empty and therefore returns 0; symbolic expressions use the same public stat.sum_x surface.

3. random

next, uniform, and normal return (value, seed). Pass seed: for a reproducible sequence, or omit it to use a clock-derived seed. uniform accepts shape: as a length or (rows, columns) and fills the result in row-major order. Like every typed function, its scalar parameters lift over compatible vectors; shared named indices align and distinct indices tensorize.

4. time

wall_time, monotonic, sleep, time_stamp, format_time, and current_time are native. Formatting accepts UTC selection and percent directives.

Browser execution supplies wall_time and monotonic through one versioned ClockArena sample per Play, tick, or event. It has no ambient host-call access. Filesystem I/O, operating-system inspection, and native process launch remain browser-forbidden and receive explicit compiler diagnostics.

5. io

print, eprint, read_line, read_text, read_bytes, write_text, write_bytes, and append_text perform native stream and file I/O.

Run in browser · 0.4.5

Native file operations use the current user's permissions and paths are not sandboxed. Browser read_text, write_text, and append_text instead use a session-scoped RAM DocumentArena. Browser paths must be normalized relative paths using /; the arena allows 64 documents, 8,192 UTF-8 bytes per document, and 49,152 live bytes total. It is cleared on refresh or reset and never grants filesystem, persistent-storage, network, DOM, or download capability.

10. .concurrent

.concurrent is the event and I/O concurrency library. It is deliberately separate from Quantum: numerical vectorization, CPU/GPU placement and kernel fusion remain compiler-managed and do not require processes or explicit threads.

concurrent: .concurrent

events: concurrent.queue()
updates: concurrent.broadcast()
state: concurrent.shared((mode:"run", samples:[1,2,3]))

worker(events, state):
    (event:events.get())??>
        Stop => state
        _ => worker(events, state)

p: concurrent.process(worker, events, state)
events.put(Stop)
:: p.join()

process(...) starts an ordinary VKF function in an isolated execution context. Its arguments use ordinary VKF call binding and spilling; there is no concurrency-specific packing syntax. p.join() waits and returns the worker result. p.kill() is forced termination; normal termination is message/program driven.

queue() is a destructive FIFO: put(value) sends one value and get() suspends efficiently until one exists. If several receivers wait, a queued value is delivered to exactly one receiver.

broadcast() permits many producers and subscribers. Each updates.subscribe() returns a queue-like branch. Every active subscriber receives every value published after subscribing; ordering from a given producer is preserved.

shared(value) takes exactly one arbitrary VKF value. It preserves normal value structure while providing compiler/runtime-selected shared backing. It does not expose mutable pointers: readers observe immutable published generations. Send small descriptors through queues and keep bulk numeric state shared rather than copying it through messages. The public API for publishing or rebinding a later generation is intentionally not specified yet.

The complete native examples separate the two communication shapes: event_pipeline.vkf uses a destructive work queue, a process and shared bulk state; and fanout.vkf gives a UI and logger their own broadcast subscriptions. They are intentionally ordinary VKF programs, not a second parallel-loop language.

The browser target resolves .concurrent but rejects reachable concurrency operations until its isolated-worker runtime is present; it never silently lowers them to host access.

12. linalg

:.linalg uses ordinary rectangular nested vectors rather than a separate matrix class. Numeric operations include dot, cross, outer, matmul, transpose, trace, determinant, rank, inverse, solve, least_squares, solution_space, rref, null_space, lu, qr, cholesky, svd, and eigen.

The same vector-lifting rule makes dot(matrix, vector) apply the declared vector-vector dot product to every compatible matrix row. Decompositions and solvers return verification metadata where convergence, residuals, or singular systems require an explicit result rather than an assumption.

13. physics And Dimensioned Units

Import the engine and units separately. :.physics.units selects the native SI catalog; :.physics.units.si is the explicit equivalent. Unit symbols are not spilled by :.physics.

Both 2km and 2 km are quantity literals. A unit supplies its scale and one seven-exponent physical dimension. Multiplication and division add and subtract dimensions; addition, subtraction, ordering, and equality require matching dimensions. The native SI catalog provides all seven bases, coherent derived units, and prefixes from quecto through quetta. SI is the only catalog currently declared; future catalogs may change names and scales but never the dimension model.


The engine surface includes 2D/3D vectors, 3×3 matrices, tetrahedral mass properties, rigid momentum stepping, collision matrices, restitution, tangential/rolling/spin friction, coupled solid contacts, materials, and the deterministic dice example. Rigid-body functions live only in physics; there is no release rigid_body compatibility module.


14. symbolic


:.symbolic provides domains N, Z, Q, R, and C; exact expression construction; elementary functions; expansion and collection; simplification; substitution; evaluation; differentiation; integration; and truncated series multiplication.


The public hierarchy is Expression, with Symbol IS Expression, Constant IS Symbol, and Relation IS Proposition IS Expression. Symbolic = and the ordered comparison operators create relations. => has lower precedence than those operators and joins propositions without parentheses. It preserves a symbolic Proposition; with two bit operands it evaluates ordinary logical implication. The same token remains the arm separator after ??, where its role is fixed by the match context.

In symbolic code, an unbound adjacent name such as xy is decomposed only when it has one unambiguous factorization into already-bound symbolic names. A real xy binding wins. Consequently 1/xy above is 1/(x*y), while the space in 1/x y resumes the outer product and gives (1/x)*y. Ambiguous factorizations are compile errors; * or parentheses always make intent explicit.


Literal adjacency uses the same multiplication rule for values and symbols: a:3; 3a+4^2 evaluates to 25, while x:R; 3x+4^2 constructs an evaluable Expression. Symbol spelling is case-preserving. Ordinary multi-character names render with \operatorname{...}; a one-character subscript stays exact (x_r renders as x_{r}), while a multi-character subscript uses \mathrm{...} (x_tot renders as x_{\mathrm{tot}}).

compile(expression, variables) produces an ordinary native function. If the listed variables resolve the expression completely, calls return numbers. 15. ui


:.ui.display provides retained, interactive 2D and 3D views. A display owns frames; each Frame.add call contributes one layer. Coordinate names state both the visual channel and the shape of the supplied data: x_i is an independent set of x coordinates, x_u is one connected path, and x_iu is a family of paths. The suffix order is the nesting order, so the outer rows of x_iu are the independent i groups and each inner row follows the connected u axis. Positional p maps component values to x, y, and z. An explicit c may appear anywhere in its suffix (p_uc, p_tcu); that axis is removed after its extent selects two or three spatial components, while all other axes keep their authored order. Without c, as in p_tiu, each leaf may instead be a two- or three-component position value.


Color follows the same rule. In c_ic or c_tc, the suffix c is the RGB or RGBA component axis and may appear anywhere; alpha is always the optional final component and defaults to 1. Numeric color components are normalized values from 0 to 1—not 0 to 255. Uniform and distributed colors may also use names or hex strings, for example color:"red" or c_i:["red","#00ff0080"].


The examples below are deliberately different programs rather than one option split into many near-duplicates. Their data is generated from ranges: i and u examples use at least 41 and usually 101 values, uv uses a 41 by 21 grid, and animation uses 101 authored t samples. add owns layer data and material; push owns limits, labels, and other properties of that view; show makes the display visible and owns display-wide options such as n_label.
